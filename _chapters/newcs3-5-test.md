## 6.1 권장 테스트 시나리오

순서대로 입력하며 각 단계가 동작하는지 확인합니다.

| # | 프롬프트 | 기대 동작 |
|---|---|---|
| 1 | "휴대폰 교체 가능성이 높은 우선 고객을 5개 관점으로 뽑아줘. 관점별 10명 + 인사이트." | SharePoint 엑셀 검색 → 코드로 분석 → 관점별 표 |
| 2 | "전체 관점에 공통으로 해당하는 고객을 최우선/우선으로 나눠줘." | 교차 분석 → 중복 고객 선별 |
| 3 | "지금까지 내용을 HTML 대시보드로 만들어줘." | 메일·보고서 스킬 → 회사 디자인 대시보드 생성·저장 |
| 4 | "이 대시보드를 나에게 메일로 보내줘." | OneDrive 업로드 → 링크 첨부 → **미리보기 + 확인 요청** |
| 5 | "발송해." | 확인 후 발송 → 결과 보고 |

## 6.2 무엇을 점검하나

- ✅ 숫자가 **코드 계산** 기반인가(눈대중·지어낸 수치 없음).
- ✅ 대시보드가 **회사 디자인**(아이보리·마젠타)을 따르는가.
- ✅ 메일이 **OneDrive 링크**로 첨부되는가(Base64 직접 첨부 아님).
- ✅ **발송 전 확인**을 거치는가.
- ✅ 스킬 리소스가 실제로 주입됐는가 → 안 되면 패키지 단계의 4.4 버그 확인.

## 6.3 자가 복구 사례 (참고)

테스트 중 에이전트가 스스로 우회한 경우들입니다 — 새 코어의 "적응" 능력.

- 전처리 스크립트가 권한 오류 → **pandas 직접 분석으로 전환**.
- 특정 ML 패키지 미설치 → **수동 정규화로 대체**.
- 임시 파일 파싱 1회 실패 → **재시도로 해결**.

> **짚고 가기:** 이런 자가 복구는 정상입니다. 다만 **스킬 리소스 누락**은 자가 복구가 안 되니, 디자인이 어긋나면 먼저 스킬 주입부터 의심하세요.
