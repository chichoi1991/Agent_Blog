## 7. 종합 — 6요소가 한 에이전트에서 맞물리는 법

<div class="info-box note" markdown="1">
**▶ 포인트** — 6요소는 따로 노는 부품이 아니라 **에이전틱 루프(1부 2장)가 소비하는 재료**다. 한 번의 요청이 6요소를 어떻게 관통하는지 보면 전체 그림이 잡힌다.
</div>

### 7.1 한 요청의 흐름 (일반형)

요청 예: **"이 데이터를 분석해서 결과를 보고서로 만들고, 담당자에게 메일로 보내줘"**

```
[지침]      항상 켜진 규칙 로드: 정확히 계산 / 확인 후 발송 / 형식은 스킬을 따름
   ↓
[참고자료]  연결된 지식(데이터 파일·문서)을 가져옴
   ↓
[스킬]      분석 스킬 로드 → "정확히 계산, 표로 정리"
[도구]      코드 실행으로 전체 데이터 집계 (RAG 아님, 1부 9.4)
   ↓
[스킬]      작성 스킬 로드 → 형식·디자인 규칙 적용 (단일 출처)
[도구]      보고서 생성 → 저장소 업로드 → 메일 초안 + 링크 첨부
   ↓
[지침]      "받는 사람 확인 + 발송 전 미리보기" → 사용자 승인 게이트
[도구]      승인 후 메일 발송
   ↓
[메모리]    대화는 세션 메모리에 기록(다음 질문에 활용), 산출물 영구보관은 저장소
```

### 7.2 전체 구성 한눈에

| 요청 단계 | 작동한 요소 | 1부 근거 |
|---|---|---|
| 규칙 적용 | 지침 | 1·2장 |
| 데이터 확보 | 참고자료 + 코드 인터프리터 | 9.4 |
| 정확 집계 | 분석 스킬 | 3장 |
| 형식 산출 | 작성 스킬 + 저장소 도구 | 3·4장 |
| 안전 발송 | 지침 HITL + 메일 도구 | 10.2 |
| 맥락 유지 | 메모리 | 9.6 |

### 7.3 빌드 순서 권장

1. **지침**부터 — 역할·가드레일·HITL을 쉬운 말로(짧게).
2. **참고자료** 연결 — SharePoint에 엑셀·Word 올리고 Knowledge 연결.
3. **핵심 스킬 1개** — 가장 중요한 것부터, 단일 파일로.
4. **도구 최소** — 코드 인터프리터 + 시나리오에 꼭 필요한 MCP만.
5. **스킬 확장** — 품질이 필요한 곳에 리소스(템플릿) 동봉.
6. **필요해지면** 연결된 에이전트로 분리.

> **반론 대응(FAQ):** "처음부터 다 갖춰야 하지 않나?" → **아니다(1부 1.4).** 지침+스킬 1개+도구 최소로 시작해 돌려보고, 막히는 지점에서만 도구·스킬·에이전트를 추가하라. 도구나 예외 규칙은 대개 **문제를 만난 뒤** 추가하는 게 정석이다.

## 부록. 빌드 체크리스트 & 흔한 함정

### 빌드 체크리스트

- [ ] 지침이 짧고 "무엇을"에 집중하는가 (구현 디테일 없음)
- [ ] 세부(색·절차)를 지침이 아니라 스킬에 뒀는가 (단일 출처)
- [ ] 비가역 행동(발송)에 확인 게이트가 있는가
- [ ] 각 스킬에 `name`·`description`(YAML)이 있는가
- [ ] `description`에 트리거 키워드가 또렷한가
- [ ] zip 루트에 `SKILL.md`가 있는가 (폴더 안 내용물을 압축)
- [ ] 스킬 `name`이 소문자·숫자·하이픈만 쓰는가 (언더스코어·대문자 불가)
- [ ] **핵심 디자인·규칙이 SKILL.md 본문에 직접 있는가** (리소스 파일은 자동 주입 안 됨)
- [ ] 도구가 최소인가 (겹치는 도구 없음, 코드로 되는 건 안 붙임)
- [ ] 숫자는 엑셀, 말투·형식은 Word로 분리했는가

### 흔한 함정

| 함정 | 증상 | 해결 |
|---|---|---|
| zip 구조 오류 | "missing root-level SKILL.md" | 폴더 아닌 **내용물**을 압축 |
| 스킬 이름 규칙 위반 | "Name must use only lowercase..." | `name`은 **소문자·숫자·하이픈**만(언더스코어·대문자 불가) |
| 같은 이름 재업로드 | 삭제·재업로드해도 옛 스킬 인식(2026-06-14 기준) | 수정본은 **새 이름(`-v2`)**으로, 미리보기로 반영 확인 |
| 번들 일부만 업로드 (프리뷰) | UI엔 정상, 실제론 YAML만 주입 → 리소스 무시 | 개인 개발환경 제약 — **Sandbox 환경에서 개발**, `app/skills` 프롬프트로 검증 |
| 리소스에만 디테일 | 에이전트가 "가이드 없다" → 제멋대로 디자인 | 핵심 규칙을 **SKILL.md 본문**에 직접(리소스는 자동 주입 안 됨) |
| 지침에 색 박기 | 스킬 우회 → 디자인 규칙 무시 | 지침은 스킬을 **가리키기** |
| 그라데이션만 사용 | 메일 흰 글씨 안 보임 | 흰 글씨엔 **단색 배경**(bgcolor) |
| 직접 첨부 | Base64 토큰 폭발·실패 | OneDrive 업로드 → **링크 첨부** |
| 도구 중복 | 도구 선택 혼란 | 목적당 **하나만** |
| 과설계 | 무거운 지침·다중 에이전트 | **단순하게 시작**, 막힐 때 확장 |
