<div class="info-box note" markdown="1">
**▶ 포인트** — 스킬은 "X를 어떻게 하는지"를 markdown 한 장(+선택 리소스)에 적어 **필요할 때만 로드** 하는 재사용 자산입니다. 효과적으로 쓰는 핵심은 (1) 단순하게 시작, (2) 모델이 혼자 못 하는 것을 인코딩, (3) `description`을 트리거로 잘 쓰기.
</div>

## 2.1 개념 — 스킬이란

- **재사용 가능한 markdown 지침 묶음.** 평소엔 컨텍스트에 없다가 그 작업이 필요할 때 **온디맨드 로드**.
- 한 번 만들면 여러 에이전트가 재사용. GitHub Copilot·Claude 스킬도 import 가능(업계 호환).
- 효과: 지침이 항상 가볍고 깨끗하게 유지됨 = just-in-time 컨텍스트.

## 2.2 SKILL.md 구조 — 필수 규격

스킬 zip은 **루트에 `SKILL.md`**가 있어야 하고, 그 안에 **YAML 머리말로 `name`·`description`**이 있어야 합니다.

```markdown
---
name: excel-analysis
description: 판매 엑셀 데이터를 분석할 때 사용. 눈대중 대신 정확히
  계산하고, 결과를 표로 정리하는 규칙. "분석·집계·평균·순위·추세" 요청 시.
---

# 판매 데이터 분석 규칙

## 언제 쓰나
[트리거가 되는 상황]

## 규칙
[지켜야 할 핵심 원칙 — 무엇을, 쉬운 말로]

## 예시
[자주 쓰는 사용례]
```

| 부분 | 역할 | 작성 팁 |
|---|---|---|
| `name` | 스킬 식별자 | 짧은 영문 슬러그 |
| `description` | **언제 로드할지 트리거** | "~할 때 사용 + 핵심 키워드" |
| 본문 | 실제 지침 | when-to-use → 규칙 → 예시 |

> **짚고 가기:** `description`이 가장 중요합니다. 오케스트레이터는 이 한 줄을 보고 "지금 이 스킬을 꺼낼까"를 판단합니다. **사용 상황 + 트리거 키워드**를 또렷이 넣어야 제때 로드됩니다.
>
> - ❌ 모호: "데이터 도우미" → 언제 쓸지 모름 → 안 불려옴
> - ✅ 또렷: "판매 엑셀을 분석할 때 사용. '분석·집계·평균·순위·추세' 요청 시." → 트리거가 분명

## 2.3 효과적으로 쓰는 법 — 3원칙

**① 단순하게 시작하라.**
처음부터 거대한 스킬을 만들지 말고, **SKILL.md 한 장으로 시작** 해 필요할 때 리소스를 붙입니다.

| 단계 | 구성 | 언제 |
|---|---|---|
| 1단계 | **SKILL.md 한 장** | 규칙·형식만 적으면 충분할 때 |
| 2단계 | SKILL.md + 보조 설명 문서 | 용어·맥락 설명이 필요할 때 |
| 3단계 | SKILL.md + 템플릿·리소스 | 산출물 품질을 고정해야 할 때 |

**② "모델이 혼자 못 하는 것"을 인코딩하라.**
스킬의 본질은 **에이전트가 스스로는 못 푸는 지식**을 적어두는 것입니다. 예를 들어, 큰 파일을 메일에 첨부하는 작업:

```
문제: 큰 HTML 파일을 메일에 직접 첨부 → 파일을 Base64로 변환하다 토큰 폭발 → 실패
해결(스킬에 인코딩): 파일 저장소(OneDrive 등)에 업로드 → 링크로 첨부
```

**③ 단일 출처를 지켜라.**
디자인 색, 절차 같은 세부는 **그 스킬 한 곳에만** 두고 지침·다른 스킬과 중복하지 않습니다.

## 2.4 단일 파일 스킬 — UI에 바로 등록

가장 쉬운 스킬은 **리소스 없는 `SKILL.md` 한 장**입니다. **Copilot Studio UI에서 그대로 붙여넣어 바로 등록** 할 수 있습니다 — zip으로 묶을 필요도, 업로드 절차도 없습니다.

```markdown
---
name: result-brief
description: 분석 결과를 매번 똑같은 짧은 형식으로 요약할 때.
  "요약·브리핑·정리" 요청 시.
---
# 결과 브리핑
## 무엇을 하나 — 항상 이 고정 형식으로 정리
  한 줄 요약 / 핵심 숫자 / 눈에 띄는 점 / 다음 액션
## 규칙
  숫자는 분석 결과만, 5줄 안팎으로 짧게, 증감은 +/-로
```

> **짚고 가기:** 처음 스킬을 익힐 때는 이 단일 파일 형태로 시작하세요. UI에 바로 등록되니 피드백이 빠르고, 스킬의 본질(재사용 지침)을 가장 또렷이 체감할 수 있습니다.

## 2.5 스킬 패키징 — 리소스를 더한 고성능 스킬

UI 단일 스킬은 파일 하나만 됩니다. 하지만 **스킬 패키징(ZIP 업로드)**을 쓰면, `SKILL.md` 지침과 함께 **참고할 파이썬 코드·HTML 양식·디자인 지침 같은 리소스를 동봉** 할 수 있습니다.

| 구분 | 단일 파일 스킬 | 패키징(ZIP) 스킬 |
|---|---|---|
| 등록 방법 | UI에 바로 붙여넣기 | ZIP 업로드 |
| 구성 | `SKILL.md` 하나 | `SKILL.md` + 리소스(.py·.html·.md 등) |
| 적합 | 규칙·형식만으로 충분 | 코드·템플릿·디자인까지 고정해야 할 때 |

> **팁 — AI 도구로 정교하게:** "이 작업을 스킬로 만들어 줘 / 이 HTML을 템플릿으로 분리해 줘 / description을 트리거가 잘 걸리게 다듬어 줘"처럼 Copilot에 맡기면, SKILL.md 구조·리소스 분리·트리거 키워드를 함께 정리해 줍니다.

<div class="info-box warning" markdown="1">
**⚠️ 중요 — 리소스는 자동 주입되지 않는다:** 스킬이 트리거되면 에이전트에 **자동으로 주입되는 건 `SKILL.md` 본문뿐**입니다. 동봉한 `design-set.md`·템플릿·`.py`는 저장만 될 뿐, **에이전트가 "필요하다"고 판단해 직접 열어야** 읽힙니다.

**원칙: 반드시 지켜야 할 최소 규칙(팔레트 값·금지·"템플릿을 쓰라")은 SKILL.md 본문에 직접 적습니다.** 확장 설명·전체 레퍼런스만 리소스 파일로 분리합니다.
</div>

## 2.6 스킬 패키징 — zip 함정 (반드시 주의)

ZIP으로 스킬을 올릴 때 **가장 흔한 실패가 이것**입니다.

| 잘못된 zip | 올바른 zip |
|---|---|
| `my-skill/SKILL.md` (폴더째 압축) | `SKILL.md` (루트) |
| → "Bundle is missing a root-level SKILL.md" | → 통과 |

**핵심: 폴더가 아니라 폴더 *안 내용물*을 압축합니다.**

- 탐색기: 폴더 안으로 들어가 → 파일 전체 선택 → 우클릭 압축.
- PowerShell: `Compress-Archive -Path "스킬폴더\*" -DestinationPath out.zip` (`\*` = 내용물)

**함정 — 스킬 이름(`name`) 규칙:** `name`은 **소문자·숫자·하이픈(`-`)만** 허용되고, 하이픈으로 시작·끝날 수 없습니다.

| ❌ 잘못된 이름 | 이유 | ✅ 올바른 이름 |
|---|---|---|
| `brand_comms` | 언더스코어(`_`) 불가 | `brand-comms` |
| `brand-comms_v2` | 언더스코어 포함 | `brand-comms-v2` |
| `Brand-Comms` | 대문자 불가 | `brand-comms` |
| `-brand` / `brand-` | 하이픈으로 시작·끝 | `brand` |

**함정 — 같은 이름 재업로드 시 옛 스킬이 남는다:** 같은 `name`의 스킬을 삭제 후 동일 이름으로 다시 올려도, 에이전트가 한동안 옛 스킬을 계속 인식하는 현상이 있습니다. 수정본은 **새 이름(`...-v2`)으로 올리는 게 가장 확실**합니다.

## 2.7 ⚠️ 프리뷰 이슈 — 개인 개발환경에서는 정상 동작하지 않음

> 현재 프리뷰 기준, **개인 개발환경(personal developer environment)에서는 New(CLI) 에이전트가 정상 작동하지 않습니다.** 스킬 패키징 업로드가 깨지는 것은 그 **증상 중 하나** 일 뿐, 개인 개발환경 전반의 문제입니다.

**확인된 이슈:** 스킬 패키징 임포트 불가(YAML만 올라가고 본문·리소스 누락) · Copilot 앱 오류 · Teams 챗봇 랜덤 비정상 동작.

**확인법 (UI를 믿지 말 것):** 테스트 프롬프트로 실제 주입을 검증합니다.

```
네가 가진 스킬 폴더의 하위 파일까지 모두 보여줘
```

- ✅ 정상: 스킬 폴더 아래 `SKILL.md` + 리소스가 **모두** 보임.
- ❌ 문제: `SKILL.md`만, 그나마 **본문이 비고 내부 포인터만** 보임.

**해결 — Sandbox 환경에서 개발.** 같은 ZIP·같은 에이전트라도 **Sandbox/일반 환경에서는 정상 동작**합니다. 스킬·설계 문제가 아니라 개인 개발환경 자체의 프리뷰 제약입니다.
